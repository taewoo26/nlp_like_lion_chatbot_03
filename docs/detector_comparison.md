# 규칙 + 모델 조합 비교표 (팀 논의용)

기준: dev 100건(정답 548개), test 200건(정답 1,165개). 기존 저장 예측을 채점한 결과입니다. **선정 결론은 팀이 정합니다.** test는 숫자 확인용이며 아래 표를 보고 규칙을 바꾸지 않습니다.

- **union:** 이름·주소·번호류 모두 규칙과 모델을 합칩니다. 겹치면 규칙 구간이 우선입니다.
- **split:** 이름·주소는 합치고, 전화·이메일·주민·계좌·카드는 규칙 결과만 씁니다.
- 전체 표의 P/R/F1은 **strict**(라벨·시작·끝 일치), 라벨 표의 P/R은 **partial**(라벨이 같고 구간이 겹치면 인정)입니다. mask_rec은 정답 개인정보 글자 중 가린 비율입니다.

## 먼저 보는 비교: split 정책

| 모델 조합 | test strict P | test strict R | test strict F1 | test mask_rec | dev 속도 평균(ms/문서) |
|---|---:|---:|---:|---:|---:|
| Veil + Kiwi | 0.9594 | 0.9948 | 0.9768 | 0.9981 | 56.27 |
| KoELECTRA + Kiwi | 0.9332 | 0.9948 | 0.9630 | 0.9985 | 9.39 |
| KoELECTRA 후처리 + Kiwi | 0.9122 | 0.9991 | 0.9537 | 0.9998 | 9.23 |

속도 열은 같은 세션에서 dev 100건을 3회 연속 실행한 예측 파일의 문서별 ms 평균(각 300건)입니다. 다른 표의 dev/test ms는 해당 채점에 사용한 첫 예측 파일의 평균이므로 속도 비교는 위 열을 우선합니다. 모델 로딩·워밍업은 제외됩니다.

## 표를 읽을 때

- 세 모델 모두 test에서 split이 union보다 전체 strict 정밀도가 높고 재현율은 같습니다. 전화번호 partial 정밀도는 세 모델 모두 split에서 1.0000입니다.
- split끼리 비교하면 Veil의 test strict 정밀도는 가장 높고(0.9594), KoELECTRA 후처리의 strict 재현율은 가장 높습니다(0.9991). KoELECTRA 기본 조합은 두 지표 사이에 있습니다.
- KoELECTRA 후처리 split의 test partial 이름 재현율은 1.0000이지만 이름 정밀도는 0.8747입니다. Veil split은 이름 정밀도 0.9494, 재현율 0.9923입니다. 이름의 오탐과 미탐 중 어느 쪽을 우선할지 팀 기준이 필요합니다.
- dev에서는 모든 조합의 재현율이 1.0000입니다. rule_kiwi 규칙은 dev 오류를 보고 개선했으므로 dev 점수는 낙관적일 수 있습니다. test도 합성 문서이므로 실제 문서 성능으로 일반화하지 않습니다.
- test 조합 6종의 3회 반복 예측은 모두 Jaccard 1.0000, 완전 동일 문서 비율 1.0000입니다. 이는 반복 일치도이며 정답률은 아닙니다.
