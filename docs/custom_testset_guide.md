# 자체 검증셋(custom) 만들기 — 가짜 holdout

목적: holdout(새 템플릿 16종)을 열기 전에, **우리가 본 적 없는 문서**에서 탐지기가 버티는지 미리 확인한다.

## 원칙
1. **탐지 코드를 만든 사람·AI가 문서를 만들지 않는다.** (규칙을 아는 쪽이 만들면 자기도 모르게 잘 잡히는 문장만 만든다)
   → GPT·Gemini 등 다른 AI, 또는 팀원이 직접 작성
2. dev 문서를 예시로 주지 않는다. 라벨 기준(아래 프롬프트)만 준다.
3. 만든 다음 **사람이 태그를 한 번 검토**한다. (LLM이 태그를 틀리게 달 수 있음 → 그러면 탐지기가 아니라 정답이 틀린 것)
4. 이 셋은 **test처럼 쓴다**: 점수 확인용. 이 셋의 오류를 보고 규칙을 고치지 않는다.
   고치고 싶으면 셋을 A/B 반으로 나눠 A만 보고 고치고 B로 확인.
5. 실제 개인정보 금지. 모든 값은 가짜.

## 순서
1. 아래 프롬프트를 GPT에 붙여 넣고 10건씩 2~3번 생성 (가능하면 Gemini 등 다른 AI로도 10건)
2. 결과를 `data/custom/gpt_1.txt`, `data/custom/gpt_2.txt` … 로 저장 (`data/`는 커밋 안 됨)
3. 팀원 1명이 태그 검토 (라벨 기준과 다르면 직접 수정)
4. 변환 → 탐지 → 채점
```bash
python scripts/tagged_to_jsonl.py data/custom/gpt_1.txt data/custom/gpt_2.txt
python -m detection.run_detect --detector rule --split custom
python -m detection.run_detect --detector veil --split custom
python -m detection.run_detect --detector hybrid_v2 --split custom
python eval/run_compare.py --gold data/custom/pii_custom.jsonl \
  --pred rule=preds/rule_custom.jsonl --pred veil=preds/veil_custom.jsonl \
  --pred hybrid_v2=preds/hybrid_v2_custom.jsonl --out results/compare_custom
```

## GPT에 붙여 넣을 프롬프트

```
너는 개인정보 탐지기 평가용 가상 데이터를 만드는 사람이야.
가상의 카드사 "새봄카드"의 사내 문서 10건을 만들어 줘. 모든 사람·번호·주소는 실존하지 않는 가짜여야 해.

[문서 종류]
- 아래 14종과 겹치지 않는 새로운 종류를 7건 이상 넣어 줘:
  카드 분실 상담, 대출 상담, 민원 처리, 고객 정보 변경, 이상거래 탐지, 연체 안내, 업무 메일,
  회의록, 인사 발령, 용역 계약서, 사내 메신저, 공지, 상품 안내, 민원 현황
  (예: 콜센터 통화 녹취록, 채팅 상담 로그, 엑셀 표를 붙여 넣은 텍스트, 감사 보고서, 교육 출석부,
   VOC 요약, 법무 검토 의견, 외부 업체 이메일 스레드, 내부 결재 문서, 설문 응답 정리 등)
- 문체를 다양하게: 구어체, 표/목록, 존댓말 메일, 짧은 메모, 대화 로그
- 길이: 문서당 3~15줄. 2건은 개인정보가 전혀 없는 문서로.

[표시 방법]
개인정보는 반드시 [[라벨:값]] 형태로 감싸. 라벨은 아래 7개만 사용.
person, phone, email, address, rrn, account, card
각 문서 첫 줄은 "### DOC 문서종류" 로 시작해. 설명이나 다른 말 없이 문서만 출력해.

[라벨 기준 — 꼭 지켜]
person (사람 이름)
- 고객·직원·외부 담당자 이름 모두 표시. 성+이름, 띄어 쓴 이름("윤 선영"), 성 없는 이름("선영 씨", "선영아")도 표시
- 태그 안에는 이름만. 직함·호칭·조사는 태그 밖: [[person:김민준]] 대리님, [[person:선영]]이가, [[person:박지호]]님께서
- 띄어 쓴 이름은 띄어쓰기 그대로: [[person:윤 선영]]
- 성 한 글자 + 직함("정 부장", "김 대리")은 표시하지 않음
- 회사명·부서명·상품명·브랜드명은 표시하지 않음 (사람 이름처럼 보여도)
phone (전화번호)
- 개인 휴대전화, 직원 직통번호 표시. 형식 다양하게: 010-0123-4567 / 01001234567 / 010.0123.4567 / 010 0123 4567 / 02-3456-7890
- 회사 대표번호(1588-xxxx 등), 내선번호, 접수번호, 민원번호, 날짜는 표시하지 않음
- 괄호·조사는 태그 밖: ([[phone:010-0123-4567]])로
email
- 아이디부터 도메인 끝까지. 도메인은 example.com / example.net / 회사명.example.com 형태로만
address (개인 거주지·배송지 도로명 주소)
- 시·도부터 마지막 호·층까지: [[address:대전광역시 유성구 미리내로 15, 302호]]
- 회사 회의실·지점명·"본사 12층"은 표시하지 않음
rrn (주민등록번호): 6자리-7자리 형식, 가짜 값
account (계좌번호): 숫자-숫자-숫자 형식만 태그. 은행명은 태그 밖: 하늘빛은행 [[account:123-456789-01]]
card (카드번호): 16자리 4-4-4-4. 카드 상품명은 태그 밖

[헷갈리게 만들기 — 꼭 섞어 줘]
- 같은 사람이 한 문서에 다른 표기로 여러 번 등장 (전체 이름 → 띄어 쓴 이름 → 성 없는 이름)
- 같은 이름의 다른 사람(동명이인)
- 사람 이름처럼 보이는 상품명·회사명, 개인정보처럼 보이는 번호(대표번호, 접수번호, 금액, 날짜)
- 이름 바로 뒤에 조사가 붙은 경우가 많게
```

## 결과 해석
- dev·test 점수와 비슷하면 → holdout에서도 버틸 가능성이 높다
- 많이 떨어지면 → 어떤 **유형**에서 떨어졌는지(라벨·어려운 사례)만 보고 보고서에 "holdout 위험 요소"로 기록
