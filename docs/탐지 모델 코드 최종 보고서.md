# 개인정보 탐지기 평가 보고서

작성: 김정하 · 최신 확인: 2026-10-27 · 현재 후보: `koelectra_post_kiwi_split` v6 + `fmt_v1` 번호·주소 개선

**목적:** 팀이 보는 판정 기준·dev/test 평가·오류 분석의 기준 문서다. Holdout의 ⑤~⑧ 산출물은 [별도 평가 보고서](holdout%20평가%20보고서.md)에서 관리한다. 설치·실행은 [사용 안내](detector_handoff.md), 초기 모델별 상세 비교는 [후보 비교표](detector_comparison.md), 모델 사양·선정 이유는 [모델 선정 근거](토큰%20분류%20모델%20선정%20분석%20보고서.md)를 본다.

## 1. 탐지 구조·평가 조건

규칙(rule_kiwi)과 KoELECTRA post를 합치며 겹치면 규칙을 우선한다. split은 전화·이메일·주민번호·계좌·카드를 규칙만 사용하고 이름·주소는 합친다. KoELECTRA는 저장소의 INT8 ONNX를 사용하며 재학습하지 않았다. post의 기본 단계는 이름 줄바꿈 분리다. 조합에서 성+직함·문맥·서식 조건을 추가한다.

평가는 합성 데이터의 원문 글자 위치 `[start, end)`와 7종 라벨을 사용한다. organization은 평가에서 제외한다. 정답 인물 목록을 이름 사전으로 쓰지 않았다. dev/test 정답은 합의 기준과 충돌하지 않아 수정하지 않았다. CPU 추론 스레드는 intra-op 2 / inter-op 1이며 모델 로딩·워밍업을 제외한 문서별 시간을 기록한다.

| 지표 | 의미 |
|---|---|
| strict | 라벨·시작·끝이 모두 같아야 정답 |
| partial | 같은 라벨로 구간이 겹치면 1:1 매칭하여 인정 |
| P / R / F1 | 정밀도 / 재현율 / 조화평균 |
| mask_rec | 정답 글자 중 예측 구간으로 가려진 비율. 과도한 마스킹도 높은 값이 될 수 있음 |
| 일관성 | 반복 예측 간 일치도. 정답률과 별개 |

재현율·mask_rec을 우선 확인하고 오탐·정밀도도 함께 본다. 운영 정밀도 하한선과 최종 탐지기 선택은 팀 결정이다. 아래 수치는 현재 정하 후보에 대한 평가이며 팀 최종 선정 결과가 아니다.

## 2. 개인정보 판정 기준

아래 기준은 `dev`/`test` 정답과 탐지 결과를 해석하는 팀 기준입니다. 먼저 정답 라벨을 이 기준으로 확인하고, 그다음 같은 기준으로 예측을 채점합니다. 탐지 결과가 정답에 없는 구간을 잡으면 오탐(FP), 정답 구간을 놓치면 미탐(FN)입니다. 라벨이나 시작·끝 위치까지 다르면 `strict` 채점에서는 FP와 FN이 함께 생길 수 있습니다. 같은 라벨의 구간이 겹치면 `partial` 채점에서는 탐지한 것으로 봅니다.

| 대상 | 판정 | 예시와 경계 |
|---|---|---|
| 성 한 글자 + 직함 | 제외 | `허 부장`, `남 부장`의 성 한 글자는 `person` 정답이 아님. 탐지하면 오탐. `허민수 부장`처럼 전체 이름이 있으면 이름 부분은 탐지 |
| 내선번호 | 제외 | `내선 7999`의 `7999`는 `phone_number` 정답이 아님. `내선`의 `내`를 이름·주소로 탐지해도 오탐 |
| 대표번호 | 제외 | `대표번호 1599-0000`, 명시된 고객센터·콜센터 번호 등 공용 연락처는 정답이 아님. 지역번호가 붙어도 **대표번호로 명시되면 제외** |
| 지점명 | 제외 | `여의도 지점` 또는 `여의도지점`은 `address`·`person` 정답이 아님. 별도로 적힌 실제 도로명 주소는 기존 주소 기준 적용 |
| 지역번호가 붙은 전체 전화번호 | 포함 | `02-3961-1452`, `031-123-4567`처럼 `02`/지역번호와 가입자 번호가 모두 있으면 `phone_number` 정답. 집 전화일 가능성을 고려해 개인 소유 여부가 불명확해도 포함하며, 위의 **명시적 대표번호** 예외가 우선 |

`070`은 지역번호가 아니므로 위 항목만으로 포함 여부를 결정하지 않습니다. `02` 같은 지역번호 **두세 자리만 단독으로** 나온 것은 전화번호 정답이 아닙니다. 회사·지점 이름 자체가 아닌 실제 사람 이름, 휴대전화 및 나머지 개인정보 유형은 기존 정답 기준을 따릅니다.

번호 구분 참고: [방송통신위원회 번호 제도 연구](https://www.kcc.go.kr/download.do?fileSeq=32037)는 `02`와 광역 지역번호를 구분하고 `070`을 인터넷전화 식별번호로 설명합니다. 개인정보 포함·제외 판정 자체는 위 팀 기준입니다.

## 5. test 오류: 이름 오탐 35건 + 경계 오류 1건

| 유형 | 건수 | 세부 내용 | 대표 문서 ID |
|---|---:|---|---|
| 회사명 전체·일부를 이름으로 탐지 | 16 | `미르보안` 8, `보안` 7, `안` 1 | D0118, D0120, D0184 |
| 상품명을 이름으로 탐지 | 11 | `하린 포인트 카드`의 `하린` | D0143, D0167 |
| 동사 표현을 이름으로 탐지 | 5 | `보고서 달래`의 `달래` | D0137, D0176 |
| 일반 단어 전체·일부를 이름으로 탐지 | 2 | `미이수` 1, `미` 1 | D0171, D0255 |
| 서식 항목명을 이름으로 탐지 | 1 | `고객명:`의 `고객명` | D0282 |
| 이름 경계 오류 | 1 | 정답 `전 서윤`, 예측 `서윤` | D0249 |
| **합계** | **36** | **이름 오탐 35 + 이름 경계 오류 1** | |

회사명·상품명은 순수 오탐 35건 중 27건(77.1%)이다. 오탐 출처는 모델 추가 34건, 규칙 1건(`고객명`)이다. 최신 재실행의 오류 분포는 기존 v6 기록과 같다.

### 남는 이유

- **다른 고유명사와 사람 구분:** 회사·상품을 모델이 사람으로 분류한다. 명사 또는 고유명사라는 품사 정보만으로 사람인지 결정할 수 없다.
- **Kiwi와 모델의 동시 오류:** 남은 `달래` 5건은 Kiwi도 `NNP`로 분석했다. 동사 분석일 때만 제거하는 현재 조건을 통과한다.
- **규칙 우선 보호의 한계:** `고객명`은 규칙도 이름으로 탐지한다. 규칙과 겹치지 않는 모델 이름만 문맥 검사하므로 이 경우를 막지 못한다.
- **띄어 쓴 이름·호칭 단서:** D0249의 `전 서윤`은 규칙 후보로 생성됐지만 Kiwi가 `전`을 관형사로 분석해 제외했다. 뒤의 공백+`님`도 강한 이름 단서로 인정되지 않아 모델이 `서윤`만 보충했다.

### 미탐과 경계 오류를 구분해서 읽기

test는 strict TP 1,164 / 예측 1,200 / 정답 1,165로 **strict FP 36, FN 1**이다. 정답과 전혀 겹치지 않는 순수 미탐은 없으며, partial FN은 0이다. FN 1은 `전 서윤`의 성을 놓친 경계 오류다. 따라서 “오류 CSV 36행”을 strict FP+FN 합계로 해석하면 안 된다. `decoy_company_phone` 등의 오탐수는 해당 태그 문서의 모든 라벨을 세므로 전화번호 오탐 8건이라는 뜻도 아니다.

## 6. 개선 효과와 해석

| 데이터 | 개선 전 strict P / R / F1 | 현재 strict P / R / F1 | 순수 이름 오탐 |
|---|---|---|---|
| dev | 0.9384 / 1.0000 / 0.9682 | 0.9928 / 1.0000 / 0.9964 | 36 → 4 |
| test | 0.9122 / 0.9991 / 0.9537 | 0.9700 / 0.9991 / 0.9844 | 111 → 35 |

성+직함 제외는 명시적인 하드 필터다. 다른 이름에는 문맥·품사·서식 구조를 적용하지만 이 역시 통과/제거 규칙이며, 학습된 가중치나 검증된 확률이 아니다. 기존 test는 반복 평가와 오류 문맥 분석에 사용했으므로 회귀 확인 자료로 해석한다.

새 합성 문맥 예제는 개선용 48문장과 별도 check 48문장을 준비했다. 개선용에서 43/48문장이 완전히 일치했으며 상품명 오탐 2, 이름 완전 미탐 2, 이름 분리 오류 1문장이 나왔다. 기존 dev/test 점수가 새 문맥에서도 유지된다고 단정할 수 없다. check는 아직 실행하지 않았다.


## 7. Holdout 평가 안내

캠프파이어 2부 산출물 ⑤~⑧(데이터 관찰·최초 성능·오류 분석·개선 및 dev/test 회귀 확인)은 [holdout 평가 보고서](holdout%20평가%20보고서.md)에 통합해 관리한다. 이 문서는 dev/test 판정 기준과 결과를 담당한다. Holdout의 최초 결과와 fmt_v1 개선 후 결과를 혼동하지 않는다.

## 8. 해석의 한계

- dev 기반 규칙과 후처리이며 test도 반복 평가·오류 문맥 분석에 사용했다. 기존 test는 회귀 확인에 사용하고 독립적인 일반화 근거라고 주장하지 않는다.
- 합성 문서와 반복 템플릿의 점수를 실제 금융 문서 성능으로 일반화하지 않는다. FP32와의 비교 및 제작자 공개 성능 재현은 하지 않았다.
- 성+직함 제외는 팀 판정 기준에 따른 하드 필터다. 문맥·품사 검사도 최종적으로는 통과/제거 규칙이다. 모델·Kiwi·규칙이 함께 틀릴 수 있다. 현재 Span에는 신뢰도가 없으며 임의 가중치를 확률처럼 설명하지 않는다.
- 번호류 split은 규칙 형식 범위에 묶인다. dev/test 지역번호 정답은 02뿐이므로 새 광역 지역번호 지원은 별도 예제에서만 확인했다.
- holdout 최초 결과를 보존했다. 이후 holdout을 보고 개선한 점수는 최초 일반화 점수와 구분하고 기존 dev/test도 재평가한다. **fmt_v1은 holdout 오류를 보고 개선한 결과이며 독립적인 일반화 점수가 아니다.**

## 9. 초기 단독 모델 비교 참고

아래는 조합 후처리 개선 전의 고정된 비교 결과다. 모델별 조합·라벨·일관성 상세 표는 [초기 후보 비교표](detector_comparison.md)에만 관리한다.

| 단독 탐지기 | dev strict F1 / mask_rec | test strict F1 / mask_rec |
|---|---|---|
| rule_kiwi | 0.999 / 1.000 | 0.986 / 0.990 |
| veil | 0.941 / 0.994 | 0.943 / 0.991 |
| koelectra | 0.908 / 0.993 | 0.877 / 0.985 |
| koelectra_post | 0.933 / 0.993 | 0.898 / 0.985 |
| moai | 0.842 / 0.919 | 0.820 / 0.903 |

초기 rule_kiwi의 test 이름 partial 재현율은 0.959로 dev보다 낮았다. 모델이 규칙의 이름 미탐을 보충하는 것이 조합 실험의 근거였다. 초기 조합 6종의 3회 반복 결과는 Jaccard 1.000이지만 최신 후처리의 반복 검증을 뜻하지 않는다.

같은 세션 dev 반복 속도 기록은 rule_kiwi 약 1.1ms, KoELECTRA post 7.5ms, 개선 전 post 조합 9.2ms, Veil 54.5ms, Veil 조합 56.3ms다. rule_kiwi의 이전 11~13ms는 첫 로딩이 섞인 것으로 보인다. 최신 결과의 별도 실행 시간과 섞어 순위를 매기지 않는다.
